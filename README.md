# Консольное ToDo-приложение на Dart

Лабораторная работа №2 по изучению объектно-ориентированного программирования (ООП) в языке Dart. В ходе работы было создано CLI-приложение для управления списком задач с возможностью добавления, просмотра, выполнения и удаления элементов.

## Запуск
1. Клонировать репозиторий:
   ```bash
   git clone <url_вашего_репозитория>
   ```
2. Перейти в папку проекта:
   ```bash
   cd lab2_todo
   ```
3. Установить зависимости:
   ```bash
   dart pub get
   ```
4. Запустить приложение:
   ```bash
   dart run
   ```

## Что изучили
1. Принципы создания классов, объявления явных типов полей, написания конструкторов и методов в Dart.
2. Использование null-safety механизмов языка и сокращенной записи конструкторов (`this.field`).
3. Переопределение системных методов (в частности, метода `toString()`).
4. Работу со статическими полями класса для инкапсуляции логики (автоматический счетчик идентификаторов).
5. Подключение внешних пакетов экосистемы Dart через менеджер пакетов `pubspec.yaml` и работу с сайтом `pub.dev`.

## Ответы на вопросы

### 1. В чём разница между полем класса и обычной переменной в функции?
* **Переменная в функции** (локальная переменная) существует только во время выполнения данной функции и уничтожается сразу после её завершения.
* **Поле класса** (переменная экземпляра) принадлежит конкретному объекту. Оно хранит состояние этого объекта на протяжении всей его «жизни» в памяти и доступно для всех методов этого класса.

### 2. Что такое конструктор и зачем он нужен?
Конструктор — это специальный метод класса, который автоматически вызывается при создании нового экземпляра (объекта). Он необходим для инициализации начального состояния объекта, передачи в него обязательных параметров и подготовки его к дальнейшей работе.

### 3. Зачем нужен `@override` перед `toString()`? Что будет если его убрать?
Аннотация `@override` указывает компилятору Dart, что мы намеренно переопределяем метод базового класса `Object` (от которого неявно наследуются все классы в Dart). Если её убрать, код всё равно скомпилируется, однако аннотация защищает от опечаток в имени метода (если написать `tostring()` вместо `toString()`, компилятор с `@override` выдаст ошибку, а без неё просто создаст новый метод, оставив системный нетронутым).

### 4. Чем статическое поле `static int _counter` отличается от обычного поля? Сколько копий этого поля существует в программе?
* **Обычное поле** дублируется для каждого созданного объекта отдельно (у каждого объекта свой `id`).
* **Статическое поле** принадлежит самому классу, а не его экземплярам. В программе всегда существует **ровно одна копия** статического поля, общая для всех объектов данного класса.

### 5. Что означает нижнее подчёркивание в `_counter`?
Нижнее подчеркивание перед именем идентификатора в Dart указывает на его **приватность (private)**. В отличие от языков вроде C++ или Java, приватность в Dart ограничивается не телом класса, а рамками **файла (библиотеки)**, в котором он объявлен. Из других файлов напрямую прочесть или изменить `_counter` нельзя.
